# Famex OS — Production Release Gates

Use this as the checklist before opening beta to 1,000 users. Every line below must have an owner, a date and a link to evidence (screenshot, log, report).

## 1. Automated testing

| Gate | Minimum standard | Status |
|---|---|---|
| Auth tests | Login, logout, password reset, session expiry, rate-limit lockout | TODO — Vitest + Playwright spec needed |
| Permission matrix | Every role × every write endpoint returns 401/403 for wrong role | TODO — seed script + per-route assertions |
| Payments | Paystack verify rejects faked references; double-submit doesn't double-charge | Partial — server-side verify exists; no replay test yet |
| Results & report cards | Locked gradebook can't be edited after publish; totals recompute correctly | Partial — `lib/gradebook.ts` locks exist; no automated test |
| CBT submissions | Refresh, double-tap and network drop don't lose or duplicate answers | Partial — idempotency keys exist; chaos test needed |
| Offline sync | Queue survives device restart; duplicate operations idempotent; conflict resolves to last-write-wins with audit row | Partial — client queue exists; conflict audit pending |

Run: `npm test` once Vitest suite is added. Target: ≥70% line coverage on `lib/*.ts` security-critical paths.

## 2. Staging environment

- Separate Postgres, separate Paystack test key, separate SMS/email sandbox.
- Migrations applied via `prisma migrate deploy` (NOT `dev` / `push`).
- Seed script loads a realistic dataset (1000 students, 40 staff, full session) so load numbers mean something.
- All new builds auto-deploy to staging before production.

## 3. Database backups

- Automated hourly WAL snapshots + nightly full dump (`pg_dump -Fc`).
- Encrypted at rest (GPG or S3 SSE-KMS) and stored in a DIFFERENT cloud region/account than production.
- Retention: daily for 30 days, weekly for 12 weeks, monthly for 12 months.
- Backups verified via script: see `scripts/backup-db.ts` (extends to restore-probe weekly).

## 4. Restore testing

- Every two weeks, restore the most recent nightly dump to a scratch database and run migrations forward.
- The restore is judged SUCCESS only when: (a) migrations apply cleanly, (b) app boots, (c) `/api/health/ready` reports healthy, (d) an admin login works, (e) a parent can view a result PDF.
- Logged in `docs/restore-log.md` with date + operator.

## 5. Monitoring

- `/api/health/ready` polled every 30 s from uptime robot / BetterStack / CloudWatch.
- Alert on 5xx rate > 1% over 2 min.
- Postgres alerts: connection saturation > 80%, storage < 20% free, replication lag > 30 s.
- Disk: data partition < 15% free → page.
- Error reporting: uncaught exceptions go to Sentry/axiom at `lib/logger.ts` integration point.
- Background jobs (`/api/jobs`) have a dead-letter dashboard.

## 6. Deployment rollback

- Every release tagged `vYYYY.MM.DD-N`.
- Migrations written in a forward-compatible way so `vPrev` can run against `vNext` DB for at least one release (add columns nullable, don't drop columns until the next-but-one release).
- Rollback is: `fly deploy --image <prev-tag>` (or Vercel "promote previous deployment") — no DB rollback needed.
- Tested: trigger a simulated bad deploy, confirm rollback completes in <5 minutes.

## 7. Database migrations

- Every `prisma/schema.prisma` change ships with a named migration under `prisma/migrations/` (auto-generated by `prisma migrate dev --name …`).
- Migrations are reviewed in PR: no DROP COLUMN without a prior deprecation release; long-running data migrations run as batched background jobs, NOT as part of the deploy.
- `post-deploy.sh` runs `prisma migrate deploy`; failure blocks traffic cut-over.

## 8. Security

- HTTPS only (HSTS preload, auto-redirect).
- Secrets never in repo; loaded from secret manager.
- Cookies `Secure; HttpOnly; SameSite=Lax`; CSRF token on mutating requests.
- Rate limits enforced at `/api/auth/login` (IP 10/15min, email 3/15min lockout).
- Audit log row for every write by privileged roles (admin, bursar, principal).
- Pen-test pass before go-live: OWASP Top 10 + auth bypass + IDOR on parent/student routes.

## 9. Offline resilience

- Device offline: attendance, CBT answers, cash fee entries are queued in IndexedDB.
- Replay sends `X-Offline-Replay: 1` header; server routes that accept offline entries MUST set status = PENDING_REVIEW (fee cash entries use `lib/fee-guard.ts` to enforce this).
- Device restart: queue persists; retry is exponential-backoff with jitter.
- Conflict resolution: last-write-wins with an audit log row; conflicting attendance marks show in `/admin/attendance-corrections`.
- Manual test: kill Wi-Fi, take 50 attendances / answer 20 CBT questions / log 10 cash payments, restore Wi-Fi, verify all reconcile in <30 s with correct audit rows and no double-posted fees.

## 10. CBT resilience

- Autosave every 10 s AND on every answer change.
- "Submit" button disabled for 2 s after click to prevent double-tap.
- Server rejects duplicate `{attemptId, questionId}` answers.
- Resume-after-close: reopening an in-progress attempt picks up from last autosaved answer, never starts a fresh attempt.
- Load test: 200 concurrent candidates submitting at T+0 on a single instance — p95 submission < 800 ms, zero 5xx.

## 11. Performance

- LCP < 2.5 s on the public home page (preload hero webp already applied).
- Admin dashboard p95 < 1 s at 200 RPS.
- Mobile GPS clock-in → confirmed response p95 < 2 s on 3G.
- CBT exam load < 3 s on a 200-question paper.

## 12. Data migration

- Legacy student data imported via the CSV import UI (`/admin/cbt/import` pattern for each domain) OR a one-off script.
- After import: total count, class balance, fee balances spot-checked against source spreadsheet and SIGNED OFF by the bursar / principal.
- A database snapshot taken immediately before migration; restore instructions posted to ops channel.

## 13. Support

- Named school administrator (primary contact during launch week).
- WhatsApp support channel staffed 8am–6pm WAT for first two weeks.
- Incident escalation matrix: on-call dev → product lead → school proprietor.
- Runbook for the top ten failure modes (Paystack outage, SMS provider down, Postgres connection exhaustion, disk full, exam-day outage, push-notification failure, parent password reset, biometric login loop, offline queue not draining, Prisma migration failure).

## Out of scope for v1 (deferred)

- Full payroll with statutory PAYE / pension / NHIF reporting — basic payroll export exists; statutory reporting is phase Q.
- Multi-campus / multi-school tenancy.
- AI tutoring / automatic question generation.
- Webcam/biometric AI proctoring for CBT.
- Integration with external LMS platforms (Google Classroom, Khan, Udemy).
